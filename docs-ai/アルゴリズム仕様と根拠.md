# 個性発見アルゴリズム 仕様と根拠

「何を使って、何を実装して、なぜ必要だったのか」を記録する文書。実装が進むたびに更新する。
計画とスケジュールは `実装計画_個性発見アルゴリズム.md`、現状整理は `実装状況と今後の見込み.md` を参照。
最終更新: 2026-11-07（絵の特徴量の保存と 5 軸への反映を追加）

## 0. この文書の読み方

- **状態**: 実装済み／実装中／未着手／取り消し／将来の発展
- **根拠の強さ**:
  - 一般的な手法: 広く使われる計算方法。ただし、子どもの個性分析に有効という意味ではない。
  - 構想由来・未確認: チームの構想に書かれていたが、元の研究を確認できていないもの。
  - 仮説: 根拠がなく、チームで決めた対応。画面と資料では「仮説」と書く。
- 診断・評価ではなく、遊びや体験を振り返る手がかりとして見せる。

## 1. 全体像（最終的に目指す形）

```
絵本ミッション（写真を撮る／絵を撮る）
        │ 端末内のみ。外部送信なし
        ▼
 ┌──────────────────────────────┐
 │ A. 色の抽出（K-means）        │ → 好きな色
 │ B. 絵の特徴量                │ → 占有率・線の細かさ・色数
 │ C. ミッションのタグ（既存）   │ → 発達領域
 └──────────────────────────────┘
        ▼
 D. 5軸（O/C/Ex/A/ES）への換算（重みは仮説）
        ▼
 E. 複数ミッションの統合 → 個性ページに反映
        ▼
 F. 習い事の提案（サンプルデータとの照合）
```

AI の実装は **端末内で動くルールベース + 機械学習の基本手法（K-means）** にとどまる。「AI が診断する」とは書かない。

## 2. 守っている制約（理由つき）

| 制約 | 理由 |
|---|---|
| 子どもの絵・写真・記録を外部に送らない | 子どもの個人情報であり、プロダクトの信頼の前提になる。 |
| 有料サービスを使わない | チームの方針。 |
| 導入（インストール・ダウンロード）は事前確認 | チームの方針。 |
| 実装していないものを、実装したと書かない | コンテスト資料の信頼性のため。 |
| デモ用の幼少期の絵は `.gitignore` に入れた | リポジトリは GitHub Pages で公開されており、誤って公開しないため。 |

## 3. 構成要素ごとの記録

### 3-1. 絵の特徴量と色の抽出（`modules/Analysis/drawingFeatures.js`）
- **状態**: 実装済み（node で 22 枚検証済み。ブラウザでも動作を確認）
- **何をするか**: 紙に描いた絵の写真から、(a) 紙を除いた代表色、(b) 描き方の特徴を取り出す。
- **使っているもの**: JavaScript のみ。外部ライブラリは使っていない。入力は RGBA の画素配列で、ブラウザと node で同じコードが動く。
- **なぜ必要か**: 構想の「画像解析（K-means で色や形）」に当たる部分。現状は、彩度の高い画素の平均色を1色取るだけで、絵の特徴を捉えていなかった。
- **方式と、そう決めた理由**:

| 処理 | 内容 | なぜそうしたか |
|---|---|---|
| 紙の色の推定 | 最も多い色の塊（隣り合う塊も合算）を紙とみなし、差し引く | 実際の絵の紙が、ピンク・白・黒い画用紙などまちまちだった。「白を除く」だけだとピンクの紙が代表色になる。暗い紙は写真でノイズが乗り、塊が散らばるため、隣も合算した。 |
| K-means（k=4、固定シード） | 紙から十分離れた彩度の高い画素を、(彩度×cos色相, 彩度×sin色相, 明度) の3次元でクラスタリング | 色相は円環なので、そのまま距離を測ると赤の両端が遠くなる。固定シードで同じ画像なら同じ結果になる。 |
| にじみの除外 | 紙との距離が小さい・彩度が低い画素を代表色から外す | 紙とクレヨンの境目のにじみが混ざると、くすんだ茶色が代表色になった。 |
| 占有率 | 紙を除いた描画の面積 ÷ 画面（外周 6% を除く） | 構想の「画面占有率」。 |
| 線の細かさ | 描画部分のうち、輪郭（隣と色の判定が変わる画素）の割合 | 構想の「描線の細かさ」。細い線やしま模様で高くなる。 |
| 使った色の数 | 色相を 45 度ごとのグループに分け、5% 以上使われたグループの数 | 構想の「色数の多さ」。 |
| 黒の割合 | 暗い・低彩度の画素の割合 | 線やぬりつぶしの把握のため。**性格の換算には使わない。** |

- **根拠の強さ**: K-means と紙の差し引きは一般的な手法。特徴量が子どもの特性を表すという点は構想由来・未確認（3-3 参照）。
- **検証結果**: 幼少期の絵 22 枚で、1 枚あたり約 10〜180ms。黒い画用紙の作品も代表色を取れた。
- **既知の限界**: 机や紙の影・紙の外の背景で、一部の画像（1-7、1-16 など）の代表色がくすむ。

### 3-2. ミッションのタグによる換算（`modules/Analysis/workStyles.js`、既存）
- **状態**: 既存のまま（今回は変更しない）。併用する。
- **何をするか**: ミッションの発達領域タグ（形・観察・色・協力など 10 種）と写真の色に、固定の重みを掛けて 5 軸へ足し込む。
- **根拠の強さ**: 仮説。コード中でも「研究用の確定対応表ではなく、調整できる仮説モデル」とされている。

### 3-3. 絵の特徴 → Big Five の対応
- **状態**: 実装済み（node で通し検証済み。ブラウザでの動作は、作成者が写真ミッションで確認済み: 好きな色と5軸の数値が変わる）
- **場所**: `modules/Analysis/workStyles.js`（`drawingTraitWeights`、`addDrawingEvidence`）
- **換算**: 各特徴を 0〜1 に正規化し、軸ごとの重みとして使う。正規化の幅は、手元の絵 22 枚で観測した範囲から決めた（占有率 0.5、線の細かさ 0.6、色数は 1 を引いて 5 で割る）。この幅にも根拠はなく、調整できる値。
- **色**: 代表色 4 色を占有率で按分し、既存の色（8 色相）の重みに足す。1 枚の絵の色が与える影響の合計は、従来の 1 色分以内。
- **後方互換**: `drawingFeatures` を持たない古い記録は、従来の 1 色の処理のまま動く。

| 特徴 | 反映する軸 | 根拠の強さ |
|---|---|---|
| 占有率が高い | 外向性 | 構想由来・未確認 |
| 線が細かい | 誠実性 | 構想由来・未確認 |
| 使った色の数が多い | 開放性 | 構想由来・未確認 |
| 色相の偏り → 情緒安定性 | **採用しない** | 根拠がなかったため外した |
| 黒の割合 | 反映しない | 判断のみ |

- **論文検索の結果（2026-11-07、簡易）**: 構想に書かれていた「描画の画像特徴が Big Five を説明できる」という実証は、確認できなかった。近い研究は、人物画の構造の機械分析（Big Five ではない）、子どもの自画像の文化差、成人の筆跡・描画と性格の研究だった。写真の近接・広角と好奇心の関係を調べた研究も、ほとんど見つからなかった。
- **扱い**: 「仮説であり、今後の検証課題」と明記する。「実証されている」とは書かない。

### 3-4. 複数ミッションの統合
- **状態**: 実装済み（単純な平均）。上限の調整は未着手
- **何をするか**: 絵本 1 冊の複数の絵・写真の特徴をまとめて集計し、1 枚の偶然の影響を平均化する。
- **なぜ必要か**: 構想の「単発ノイズを減らすマルチモーダル統合」に当たる。デモで「絵を足すほど結果が変わる」様子を見せる土台にもなる。
- **方式**: 既存の仕組みのまま、すべてのミッションの証拠を足して件数で割る（単純な平均）。絵が増えるほど 1 枚の影響が小さくなる。
- **保存**: ミッション達成時に `drawingFeatures`（代表色・占有率・線の細かさ・色数・黒の割合。画像そのものは含まない）を保存する。`modules/Preview/index.js` → `js/Session.js`（`runMissions` と日記エントリ）。
- **検証結果**（絵 22 枚、タグは仮の領域を巡回）: 絵が 0 枚のときは固定の初期値（O72 C78 Ex66 A84 ES70）、1 枚目で実測に切り替わり、その後は枚数が増えるほど値が安定する。枚数による変化は、最初の数枚で大きく、後半は小さい。デモでは、絵の順番を選ぶと変化が見えやすい。

### 3-5. 習い事の提案
- **状態**: 実装済み（実ブラウザで確認済み。データはサンプル）。コード: `modules/Analysis/traitText.js`、データ: `content/extracurricular-sample.json`
- **何をするか**: 分析画面の「性格」「好きなこと」「習い事の提案」を、記録から作る。LLM は使わない。記録がないときは、従来の固定の見本文を出す。
  - 性格: 5 軸のうち値が高い上位 2 軸の短い文を組み合わせる（軸の最大と最小の差が 3 未満なら作らない）。
  - 好きなこと: 記録で付いたタグが多い上位 2 つを、言い換えて表示する。物体認識は入れていないので、「動物・乗り物」は出せない。
  - 習い事: 習い事ごとの「向いている軸」「向いている領域」を使い、点 = (その軸が 5 軸の平均より高い分の平均) + 20 ×(向いている領域のタグが記録に占める割合)。上位 2 つを出す。
- **データ**: サンプル（モック）。画面と資料に「サンプルデータ」と明記する。聞き込みで作ったデータに差し替えられる形にする。
- **文面の対応表**（`traitText.js`。直すときはここを編集する）:
  - 性格（軸 → 文）: 開放性「好奇心旺盛」／誠実性「ていねい」／外向性「のびのび表現」／協調性「やさしく人を思いやる」／情緒安定性「落ち着いて取り組む」。
  - 好きなこと（タグ → 言い換え）: 形「かたちづくり」／観察「じっくり見ること」／自然「しぜんやいきもの」／感覚「さわって感じること」／色「いろあそび」／もよう「もようあそび」／表現「お絵かき・表現」／協力「みんなでやること」／生活習慣「身のまわりのこと」／自立「自分でやってみること」。
  - 習い事: `content/extracurricular-sample.json` の 8 件（図工・造形、リトミック・音楽、自然体験・野外、そろばん・学習、スイミング、キッズダンス、チームスポーツ、ものづくり・プログラミング）。
- **根拠の強さ**: 仮説。文面は作成支援の AI（Claude）が、Big Five の一般的な説明を参考に書いた。研究や聞き取りで確かめた対応ではない。習い事の 8 件と「向いている軸・領域」は仮の内容で、実在の教室の調査ではない。発表・資料では「サンプルデータと仮説のルールによる表示で、診断ではない」と書く。

### 3-6. デモ用の取り込みと表示
- **状態**: 実装済み（実際のブラウザで確認済み）。動画の撮影は 11/9 以降
- **場所**: `modules/Analysis/demo.js`、`modules/Analysis/index.js`、`content/demo/demo-drawings.json`
- **何をするか**: URL に `?demo=1` を付けたときだけ、分析画面に「絵を足す」パネルを出す。端末内のファイルから絵を複数枚選び、「つぎの絵を足す」を押すごとに、5 軸と好きな色が変わる。
- **なぜ必要か**: 発表で、絵を入れると個性ページが変わる様子を動画で見せるため。
- **作りの判断**:
  - 実際の保存データには書き込まない（デモ専用の記録で分析する）。本物の記録と混ざらず、画面を開き直せば消える。
  - 絵と発達領域タグの紐づけは、JSON で作成者が決める（絵本ごとのミッションが 1〜3 個しかなく、22 枚を一対一で割り当てられないため）。タグは直接書くか、`missionId` を書いてミッションから引き継ぐ。
  - 絵か写真かの区別は、デモでは「取り込んだものは絵」とする（取り込み時の指定）。
  - 絵の画像は、プロジェクトの外に置く。`serve.py` が同じ Wi-Fi の端末にフォルダを公開するため。
- **検証結果**: 絵 4 枚を順に足したところ、5 軸は 72 78 66 84 70（初期値）→ 61 50 62 45 41 → 59 49 74 41 39 → 57 50 79 40 40 → 58 49 80 40 41 と変化した。色は「赤系×2・オレンジ系×2・緑系・水色系」。リセットで初期値に戻る。
- **撮影**: 11/9 以降。

## 4. 実装しないもの（理由つき）

| 項目 | 理由 |
|---|---|
| 写真の物体認識（「好きなもの」） | 学習済みモデルの導入が必要。今回はビジネスコンテストのため見送り。将来の発展。 |
| VLM / LLM の API | 子どもの写真を外部に送ることになり、有料でもある。 |
| 深層ニューラルネットワークによる Big Five 推定 | 正解データ（子どもの絵・写真と Big Five の組）がない。 |
| 古典テスト理論による行動解析 | 質問票の設計が必要で、期間に収まらない。 |
| コサイン類似度（職業マッチ） | 一度実装したが、取り消した。現状は、差の絶対値の平均で近さを出している。再検討する場合は、標準化が要る。 |
